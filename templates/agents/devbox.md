# Скоуп DevBox — как здесь работать

Ты работаешь в скоупе DevBox: это папка `/workspaces/tree` в контейнере, в ней лежат несколько
репозиториев и папка конфигов `.devbox`. Окружение (репозитории, инструменты, секреты, MCP)
производится из этих конфигов. Ниже — как им пользоваться. Этого достаточно; не изобретай обходов.

## Что где

| Что | Где задаётся | Как применить |
|---|---|---|
| какие репозитории в скоупе | `.devbox/mani.yaml` | `devbox sync` |
| какие инструменты и их версии | `.devbox/mise.toml` | `devbox sync` |
| секреты и переменные | `fnox set -g ИМЯ` (шифртекст в `.devbox/fnox/config.toml`) | новый терминал |
| MCP-серверы | `.devbox/mcp.json` | перезапуск агента |
| какие пакеты соседа линковать | `.devbox/links.yaml` | `devbox link <приложение>` |
| скрипты скоупа | `.devbox/.vscode/tasks.json` | — |

Правило: правится только `.devbox`. Файл окна `tree.code-workspace`, ссылки в корне скоупа и этот
файл производит девбокс — руками их не меняй.

Ни один репозиторий ничего не делает «под девбокс»: не добавляй в репозитории файлы, настройки или
скрипты ради скоупа. Зависимости каждого репозитория живут в нём самом, общей установки нет.

## Линк приложения на пакеты из соседней папки

Нужен, когда правишь пакет (например `web-core`) и хочешь сразу видеть правки в приложении.

```sh
devbox link statboard      # приложение берёт пакеты из соседней папки
devbox unlink statboard    # вернуть как было: пакеты снова из реестра
```

Что делает `devbox link` — и это штатно, чинить не надо:

- дописывает в `pnpm-workspace.yaml` приложения блок `overrides` со ссылками `link:../…`;
- запускает `pnpm install`, и тот **переписывает `pnpm-lock.yaml`** на локальные пути;
- если надо, пересоздаёт `node_modules` приложения.

Пока линк стоит:

- **не коммить** `pnpm-workspace.yaml` и `pnpm-lock.yaml` приложения;
- не откатывай их через git и не делай резервных копий — прежние версии лежат в git, и
  `devbox unlink` сам возвращает оба файла и ставит зависимости из реестра;
- не запускай установку с ключами вроде `--frozen-lockfile`, `CI=true`, `lockfile=false`.

`devbox unlink` ставит пакеты из реестра. Если реестр недоступен, он так и скажет: файлы уже
возвращены, в `node_modules` остались ссылки — повторить `pnpm install`, когда реестр появится.
Это не поломка.

Команда отказывает, если в этих двух файлах есть чужие незакоммиченные правки, — тогда скажи об
этом человеку, а не обходи.

## Секреты

Переменные из секретов скоупа уже есть в окружении терминала. Значения не печатай и не читай без
нужды; новый секрет задаёт человек: `fnox set -g ИМЯ`.

## Если чего-то не хватает

Нет инструмента — он называется в `.devbox/mise.toml`, после чего `devbox sync`. Не ставь
инструменты в обход (`npm i -g`, `apt`, `curl | sh`). Если команда девбокса упала или ведёт себя
не так, как здесь описано, — остановись и покажи человеку её вывод: это ошибка девбокса, а не
повод искать обход.

Полный список команд: `devbox help`.
